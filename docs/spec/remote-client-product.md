# Vhostty 远程客户端 MVP

状态：产品范围已确认，尚未实现。更新日期：2026 年 10 月 14 日。

用户通过 iPhone 或另一台 Mac 上的 Vhostty，连接自己的电脑，查看项目、会话和历史，继续操作电脑上的 Claude Code / Codex。会话和任务实际运行在被连接的电脑上。

正文规定产品范围和用户行为；文末“技术限制”单独记录已讨论的技术方案与验证要求。

## 平台与连接

- iPhone 端只能作为远程客户端，不提供本地会话模式。
- 桌面端支持本地使用，也支持作为远程客户端连接另一台电脑。本地使用保留现有功能；本文的功能裁剪只适用于远程模式。
- 远程客户端要求用户输入服务 URL。客户端与服务端之间的安全联通由用户自行保证。
- MVP 不做账号系统、配对码或访问凭证。
- 界面清楚区分当前是本地还是远程，以及正在连接的电脑，避免误操作另一台电脑的会话。
- 远程连接不迁移项目或执行环境。代码、工具和会话进程仍在被连接的电脑上。

## 本地端开放远程服务

- 远程服务默认关闭。
- 在 macOS 顶部的 **Vhostty 菜单**中提供勾选项“允许远程连接”，控制本机是否开放远程服务。
- 记住开关设置；开启后，下次启动 Vhostty 自动开放远程服务。
- 同一菜单中提供“远程连接信息…”入口，展示服务地址、端口及是否已有远程客户端连接。
- 不另做复杂的服务管理页面。此设置属于提供服务的本地端，远程客户端不管理它。

## 产品形式

项目列表、会话卡片、会话历史等内容按设备尺寸展示。进入会话后显示并操作该会话的终端，沿用 Claude Code / Codex 原有的输入、菜单和交互确认。

MVP 不另做聊天式会话界面，不把 agent 的终端交互重新设计成消息卡片或业务按钮。

### iPhone 终端按键栏

在 iPhone 系统软键盘上方提供一排附加按键：**Esc · Tab · Shift+Tab · Ctrl+C · ← · ↓ · ↑ · →**。

八个按键均纳入 MVP，点击即向当前会话发送对应按键。Shift+Tab 和 Ctrl+C 使用独立按钮，无需用户组合输入。普通文字继续使用系统软键盘输入。

## 功能范围

| 功能 | 远程端 MVP 行为 |
| --- | --- |
| Projects | 只读浏览被连接电脑已有的项目，不提供项目管理操作 |
| Session cards | 保留会话卡片，支持查看、新建、resume 和关闭 session |
| Live status | 保留，展示被连接电脑上的实际会话状态 |
| Notifications | 保留客户端连接期间的通知 |
| Session history | 保留，可浏览并 resume 历史会话 |
| Bottom shell | 不提供 |
| Closed-lid sleep protection | 完全不参与，不读取或展示状态，不提供设置或初始化弹框 |
| Scheduled tasks | 完全不参与，不读取或展示状态，不提供管理页面或操作 |

除终端内的正常输入外，远程界面改变会话的操作只有三个：**新建 session、resume session、关闭 session**。不增加项目编辑、排序、会话重命名、定时任务管理等操作。

浏览、选择会话以及连接电脑属于使用客户端的必要操作，不增加被连接电脑的管理能力。

## 项目与会话

### 项目只读

远程端展示被连接电脑的项目。添加、移除、编辑项目及修改项目设置均在本地端完成；远程端不提供这些入口。

### 新建 session

用户在已有项目下新建 Claude Code 或 Codex 会话。默认 agent 沿用该项目在本地端的设置，远程端不修改默认设置。

创建成功后显示对应卡片并可进入终端。本地端同步看到该会话。

同一次新建操作不能因网络中断或重试产生多个会话；用户再次明确执行新建，则创建另一个会话。

### 打开运行中的 session

点击已经运行的卡片，进入同一个会话，不另外启动一个副本。手机与桌面操作的是被连接电脑上的同一个会话。

### Resume session

从 Session history 恢复原会话，保留原有上下文。若该会话已经打开，则进入已有卡片，不再重复启动。

恢复失败时显示失败，不擅自替换成新会话。

### 关闭 session

**点击卡片上的“关闭 session”，关闭被连接电脑上的对应 session，行为与本地端关闭一致。** 沿用本地关闭所需的确认规则，远程用户能够在当前客户端完成确认。本地端与远程端同步更新，历史仍按现有行为保留并可 resume。

关闭只作用于用户选中的 session，不影响其他会话。

### 本地与远程界面各自独立

远程端浏览、切换项目或会话，以及新建、resume session，都不改变本地界面当前选中的项目和会话。本地界面只同步卡片的增加、移除和状态变化，不跟随远程端切换画面；远程端同样不跟随本地端切换。

因此两端可以同时操作不同的 session。例如 iPhone 在 session A 中输入，本地同时在 session B 中输入，两者互不影响：A 按 iPhone 的行列数显示，B 保持本地行列数。两端同时操作同一个 session 时，按下文终端尺寸规则处理，由用户自行避免同时输入。

典型场景是同一用户离开电脑时用 iPhone，回到电脑前用本地端：回到电脑前看到的仍是离开时选中的 session，不会被 iPhone 上的浏览打乱；iPhone 未锁屏留在一旁时，两端也不会互相拉动画面。

## 连接中断与恢复

本节描述连接生命周期，与点击卡片上的“关闭 session”是独立行为。

- 远程客户端断网、退出 App 或主动断开连接，不等于关闭 session，不因客户端离开而结束电脑上的会话。
- iPhone 切到后台或锁屏时，用户无需手动断开，客户端也不因切后台主动断开。后台连接可能被系统挂起或中断，不保证持续在线。
- 返回前台时，普通网络中断可以自动重连；若连接已被其他客户端替换，则提示“已在其他设备连接”，保持断开，直到用户手动连接。
- 连接中断时明确显示不可用状态，不把旧的会话状态显示成仍在实时更新。
- 重新连接后恢复项目、卡片、历史和实际运行状态，并能够继续查看、操作原会话。
- 电脑上的任务是否能够继续，取决于电脑和本地端的实际运行情况；远程端不负责唤醒电脑或改变休眠设置。

## 单客户端连接与终端尺寸

- 每台服务端同时只允许一个远程客户端连接，iPhone 与桌面远程客户端共用这一名额。
- 新远程客户端连接成功后，自动替换旧连接，无需先在旧设备上手动断开。会话继续运行，本地输入不受影响。
- 被替换的客户端提示“已在其他设备连接”，不自动重连；用户可手动连接，避免客户端之间反复抢占。
- 终端尺寸以最近一次变化为准：远程端进入 session、调整窗口大小或 iPhone 回到前台时，按远程端尺寸显示；本地调整窗口大小时，按本地尺寸显示。
- 本地端与远程端每次发送输入时，都使用当前端的终端尺寸；若与会话当前尺寸不同，先调整尺寸再处理输入。因此 iPhone 即使始终停留在前台，也会在再次输入时恢复手机尺寸，无需重新进入会话或点击按钮。
- 各端（本地端、iPhone 与桌面远程客户端）触发输入尺寸对齐的操作仅限键盘输入（包括 iPhone 软键盘和按键栏的 8 个键）和粘贴。滚动查看历史、点击和选择文本均不触发尺寸对齐，即使这些操作会作为鼠标事件发送给会话。进入会话、回到前台及显示区域尺寸变化仍按上述尺寸规则处理。
- 尺寸对齐改变的是会话的行列数，不改变本地或远程窗口的大小。行列数取当前操作端显示区域实际能容纳的大小；本地输入时使用本地显示区域的当前行列数。
- 本地端与远程端均可输入，不锁定本地输入；由用户自行避免同时操作。
- 远程端离开该 session 或断开连接后，该 session 恢复本地终端尺寸。
- 不设置“查看／接管”模式或接管按钮，不进行多个远程客户端之间的尺寸协商。
- 会话使用远程端行列数时，本地窗口和显示区域保持原大小，不增加“正在按远程设备尺寸显示”等提示。

## Live status、历史与通知

Live status 和 Session history 以被连接电脑的实际信息为准。远程客户端保留查看运行状态、浏览历史和恢复会话的能力。

通知保留已有会话通知的含义，不增加定时任务通知中心或额外管理功能。MVP 只覆盖客户端连接期间的通知，**不实现 iPhone 退到后台或锁屏后的可靠推送**。

## 远程端完全不参与的功能

### Closed-lid sleep protection

远程端不读取状态、不展示状态、不提供设置、不触发或承接本地初始化弹框。相关行为完全依赖本地端已有的设置和运行情况。远程端对此功能无感。

### Scheduled tasks

远程端不读取任务状态、不展示任务列表、详情或运行记录，不提供创建、修改、启停、删除或立即运行入口，也不承接相关管理弹框。

即使用户通过 skill 创建或操作了定时任务，远程端也不增加处理流程或管理能力。定时任务仍按本地端既有规则运行，远程端对此功能无感。本范围不改变 [定时任务产品设计](schedule-product.md) 中的本地行为。

### Bottom shell

远程端不显示底部 shell，不提供打开入口或对应快捷操作。

## MVP 验收重点

- 远程客户端验收仅覆盖同一台 Mac 上的 iOS 模拟器和桌面远程客户端，均通过 `127.0.0.1:端口` 连接本机隔离的测试服务端。iPhone 真机、另一台电脑和跨网络连接不在本次验收范围内。
- 两种客户端分别验收，并通过依次连接同一测试服务端验证新连接替换旧连接、旧客户端不自动抢回的行为。
- iPhone 系统软键盘上方提供 Esc、Tab、Shift+Tab、Ctrl+C 和四个方向键，可操作当前会话的菜单和输入；组合键按钮一次点击即可发送。
- iPhone 只提供远程使用；桌面能本地使用或连接另一台电脑。
- 本地远程服务默认关闭；Vhostty 菜单提供“允许远程连接”勾选项并记住设置，下次启动沿用。
- “远程连接信息…”展示服务地址、端口与客户端连接状态。
- 输入 URL 即可发起连接，不要求账号、配对码或访问凭证；客户端与服务端之间的安全联通由用户自行保证。
- 远程端能浏览已有项目，但没有项目管理入口。
- 能新建、resume 和关闭 session；打开已运行会话不会新建副本。
- 新建操作重试不重复创建；重复 resume 已打开会话不重复启动。
- 关闭卡片与本地关闭行为一致，确认可在远程端完成，本地端与远程端同步更新。
- 远程端切换项目或会话、新建或 resume session，本地界面当前选中的项目和会话不变，反之亦然；两端可同时在不同 session 中输入，互不影响。
- 每台服务端同时只保留一个远程客户端连接；新连接成功后替换旧连接，会话继续运行。旧客户端显示“已在其他设备连接”，不自动重连。
- iPhone 切后台或锁屏无需手动断开，也不主动断开；返回前台可恢复普通断线，但不能自动抢回已被其他客户端替换的连接，包括后台期间未收到替换提示的情况。
- 终端尺寸以最近一次变化为准：远程端进入 session、调整窗口大小或 iPhone 回到前台时使用远程尺寸，本地调整窗口大小时使用本地尺寸；远程端离开后恢复本地尺寸。本地端与远程端均可输入，无需手动接管。
- iPhone 始终在前台时，本地手动放大终端后，手机再次输入会先恢复手机尺寸；随后本地输入也会先恢复本地尺寸，不需要额外按钮。
- 各端只有键盘输入（包括 iPhone 软键盘和按键栏 8 个键）和粘贴触发输入尺寸对齐；在任何一端滚动历史、点击和选择文本都不触发。对齐只调整会话行列数，不调整任何窗口大小。
- 断开连接与关闭 session 分开处理；重连后能继续进入原会话。
- Live status、Session history 和连接期间的 notifications 保留。
- 不实现 iPhone 后台或锁屏可靠推送。
- 远程端没有 Bottom shell、项目管理、休眠保护和定时任务管理入口。
- 休眠保护与定时任务的状态、设置、初始化或管理弹框不会进入远程端；skill 操作也不改变这一范围。

## 技术限制

### 通信与协议定义

- 当前技术方案为一条 WebSocket 连接配合 Protobuf 消息定义。项目、会话、历史查询，会话操作，以及实时终端数据、状态和通知共用这一连接，不另拆 HTTP 业务接口。
- 使用独立的 `.proto` 文件定义消息和字段，并生成客户端与服务端使用的代码。iPhone 与桌面远程客户端共用同一份协议定义，通过 WebSocket 通信。
- 在 `.proto` 的消息定义和注释中写清楚版本兼容、请求与回复对应关系、错误返回、重复请求处理、重连恢复，以及单客户端连接限制、终端尺寸与输入行为。
- 客户端从用户填写的 URL 建立连接，不依赖 Vhostty 自建的云端转发服务。客户端与服务端之间的安全联通由用户自行保证。

### 终端与执行环境

- Claude Code / Codex 继续运行在被连接的电脑上。手机内嵌终端显示和输入组件，不在手机上运行这些 agent 或本地项目。
- PTY 是电脑本地的终端接口，不是网络协议。远程连接传输终端输入输出字节和控制消息，客户端解析终端输出；用户输入写入对应会话的终端，不依赖模拟系统键盘或聚焦桌面窗口。
- iOS 优先评估原生 libghostty 集成。已有 [gterm](https://github.com/madeye/gterm) 和 [libghostty-spm](https://github.com/Lakr233/libghostty-spm) 等参考项目，但包含 iOS 适配和补丁，不能假定桌面端现有集成可以直接复用。具体依赖与适配方式需通过构建和运行验证后确定。
- 同一个 PTY 只有一套行列尺寸，采用最近一次由本地或远程端触发的尺寸变化。远程端进入 session 或 iPhone 回到前台时重新提交远程尺寸，离开后恢复本地尺寸；不实现本地与远程之间的输入锁定，也不因另一端的尺寸同步反复覆盖。
- 本地端与远程端每次发送输入时，一并携带当前端实际可用的终端行列数。服务端先比较会话尺寸，仅在不同时调整，再处理该次输入。当前端尺寸取自自身显示区域，不使用另一端同步过来的会话尺寸；该规则写入 `.proto` 定义和注释。
- 各端的输入尺寸对齐仅由键盘输入（包括 iPhone 软键盘和按键栏 8 个键）和粘贴触发；滚动历史、点击和文本选择即使作为鼠标事件写入会话，也不走输入尺寸对齐流程。调整 PTY 行列数不调整客户端窗口或显示区域大小。
- 重连不能只继续接收新输出，还需要恢复当前终端画面及必要的滚动历史；客户端断线不应销毁电脑上的会话。

### 会话操作与通知

- 现有本地 resume 会检查已打开的 session，已有终端不会因再次选择而重复启动；远程操作应复用这一行为。
- 现有新建操作每调用一次都会创建一个会话。远程请求需区分“同一次操作的重试”和“用户再次新建”，前者返回原结果，后者才创建新会话。
- 客户端不提取 Claude 的订阅凭证或自行代替 Claude Code 请求模型服务；agent 的登录和模型访问仍由电脑上的原版程序负责。
- WebSocket 连接不保证 iPhone 在后台或锁屏时持续运行。MVP 不引入后台可靠推送，仅保留客户端连接期间的通知。

### 开发与验证环境

- iPhone 客户端的构建和模拟器验证需要完整 Xcode 及 iOS Simulator runtime，仅安装 Command Line Tools 不够。
- iOS 的界面、连接、终端交互、软键盘及中文输入均在本机 iOS 模拟器中验收，本次不要求 iPhone 真机验证。
- 本机桌面远程客户端与本机 iOS 模拟器均通过 `127.0.0.1:端口` 连接隔离的测试服务端。服务端本地界面用于核对会话同步、独立选择和尺寸规则，不要求另一台电脑或跨网络验收。
- 测试使用隔离项目与会话，不向用户真实会话发送测试输入。
