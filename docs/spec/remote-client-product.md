# Vertty 远程客户端 MVP

状态：MVP 已实现。服务端、Mac 远程窗口和 iPhone / iPad app 已完成，客户端界面按“代码共享”的要求与本地端共用一套代码。内置 Tailscale 连接（见“连接方式”）已实现。更新日期：2026 年 10 月 16 日。

用户通过 iPhone、iPad 或另一台 Mac 上的 Vertty，连接自己的电脑，查看项目、会话和历史，继续操作电脑上的 Claude Code / Codex。会话和任务实际运行在被连接的电脑上。

正文规定产品范围和用户行为；文末“技术限制”单独记录已讨论的技术方案与验证要求。

## 平台与连接

- iPhone / iPad 端只能作为远程客户端，不提供本地会话模式。
- 桌面端支持本地使用，也支持作为远程客户端连接另一台电脑。本地使用保留现有功能；本文的功能裁剪只适用于远程模式。
- 两种连接方式（见“连接方式”）：
  - **Tailscale**：Vertty 内置 Tailscale。两端登录同一个 Tailscale 账号即完成组网，客户端从列表里选电脑，不填地址。
  - **自行组网**：用户输入服务 URL，客户端与服务端之间的安全联通由用户自行保证。给已经自己组好网的用户。
- Vertty 不做自己的账号系统、配对码或访问凭证。Tailscale 方式的身份就是用户的 Tailscale 账号。
- 界面清楚区分当前是本地还是远程，以及正在连接的电脑，避免误操作另一台电脑的会话。
- 远程连接不迁移项目或执行环境。代码、工具和会话进程仍在被连接的电脑上。

## 本地端开放远程服务

- 远程服务默认关闭。
- 在 macOS 顶部的 **Vertty 菜单**中提供子菜单“远程连接”，三选一，当前一项打勾：

  ```
  远程连接 ▸  关闭
            ✓ 通过 Tailscale
              自行组网
              ──────────
              Tailscale：user@example.com
              本机名称：my-mac-vertty
              远程客户端：未连接
              退出 Tailscale 登录
  ```

  - 两种方式不同时开放：选 Tailscale 时，服务只在 Tailscale 网络上开放，不在局域网等其他网络上监听端口。
- 记住选择；开启后，下次启动 Vertty 按同一方式自动开放远程服务。
- 像菜单栏 Wi-Fi 菜单显示网络详情那样，在子菜单的选项下方（分隔线之后）用灰色行显示当前方式的详情；关闭时不显示分隔线和详情。不列出本机地址，不另设信息窗口。
  - 自行组网：端口和已连接的远程客户端（未连接时显示“未连接”）。
  - 通过 Tailscale：登录的 Tailscale 账号、本机在 Tailscale 里的名称和已连接的远程客户端，以及“退出 Tailscale 登录”。未登录时显示“等待登录”和“登录 Tailscale…”（见“连接方式”）。
- 自行组网使用固定默认端口 **58563**。用户可通过环境变量 `VERTTY_REMOTE_PORT` 修改端口，重启 Vertty 后生效；不提供界面端口设置，不自动改用随机端口。Tailscale 方式固定使用 58563，不受该变量影响。
- 服务启动失败时，仅在子菜单的详情里显示“启动失败”和具体原因，不弹窗、不自动重试。选择保留用户设置，不能将已选显示为服务已成功启动。
- 不另做复杂的服务管理页面。此设置属于提供服务的本地端，远程客户端不管理它。

## 连接方式

### 通过 Tailscale

两端（提供服务的电脑和远程客户端）各自登录用户自己的 Tailscale 账号。登录同一个账号，即可互相连接，不需要安装 Tailscale App，不用填地址。

- **登录**：用系统标准的网页登录窗口打开 Tailscale 的登录页（可用 Google、GitHub、Apple 等账号），不打开默认浏览器、不跳出 App：先出系统确认框“‘Vertty’想要使用‘…tailscale.com’登录”，继续后 Mac 上是一个单独的小窗口，iOS 上是 App 内弹出的网页。登录状态与 Safari 共用。登录完成后窗口自动关闭并生效，无需再确认；用户也可以自己关掉窗口放弃。
  - 电脑端：在“远程连接”中选“通过 Tailscale”时如果未登录，自动打开登录页一次；之后菜单显示“等待登录”和“登录 Tailscale…”（再次打开登录页）。登录前不算远程服务已开放。
  - 客户端：连接页的“用 Tailscale 登录”按钮。
- **退出登录**：电脑端在菜单里，客户端在连接页。退出后这台设备离开 Tailscale 网络；电脑端仍保留“通过 Tailscale”的勾选，显示“等待登录”。
- **选电脑**：客户端登录后列出同一 Tailscale 账号下的 Vertty 电脑（在线的在前，显示在线 / 离线），点一台即连接。没有可连的电脑时提示：“没有找到电脑。请在电脑上的 Vertty 菜单“远程连接”中选择‘通过 Tailscale’，并登录同一个 Tailscale 账号。”
- **访问限制**：电脑只接受同一个 Tailscale 账号下的设备。别人分享给用户的设备，或用户分享给别人的这台电脑，都连不进来。
- **登录过期**：Tailscale 的设备登录会过期（默认约 180 天，用户可在 Tailscale 后台关闭过期）。过期后电脑端菜单显示“等待登录”，客户端连接页显示未登录，用户重新登录即可。
- 在 Tailscale 后台，Vertty 的电脑和客户端各是一台独立的设备，名称带 `vertty`，与用户自己安装的 Tailscale App 互不影响。同一台 Mac 的远程服务和远程客户端共用一台设备、一次登录。
- 连接、重连、被替换和自动连接上次电脑的规则与自行组网相同。iPhone 回到前台时，Tailscale 需要一两秒恢复网络，按普通断线重连处理。

### 自行组网

即原有方式：远程客户端输入电脑的地址和端口（如 `192.168.1.5:58563`）。客户端与服务端之间的安全联通由用户自行保证（例如自己的 VPN）。

### 客户端连接页

iPhone / iPad 打开后、Mac 选择“文件 → 连接远程电脑…”时显示连接页，两部分上下排列：

1. **Tailscale**：未登录时是“用 Tailscale 登录”按钮；登录中显示“请在弹出的窗口中完成 Tailscale 登录”和“重新打开登录页”；登录后是电脑列表，下方显示登录账号和“退出登录”。
2. **自行组网**：地址输入框和“连接”按钮。

Tailscale 在上，作为主要方式；自行组网一直可用。

## 产品形式

项目列表、会话卡片、会话历史等内容的外观和交互与本地端一致，只在设备尺寸和输入方式不同处调整：

- Mac 远程窗口和 iPad 与本地窗口相同，左侧栏加右侧终端。
- iPhone 把侧栏作为一整屏，点卡片进入该会话的终端，返回回到侧栏。
- iPhone 只支持竖屏（横屏弹出键盘后终端几乎没有空间）；iPad 支持横竖屏。
- iPhone 和 iPad 用手指操作：文字和间距按比例放大（项目名约 17pt），项目、历史、“显示更多”等可点的行至少 44pt 高，布局和样式不变。
- 本地的右键菜单在触屏上用长按打开；只在鼠标悬停时出现的按钮（如卡片的关闭按钮），触屏上通过长按菜单提供。例外是项目行的“搜索”和“新会话”：触屏上一直显示，点“新会话”新建项目的默认类型，长按它选择新建 Claude 或 Codex 会话；长按项目名仍打开项目菜单。
- 本地端有、远程端不提供的功能（见“功能范围”），在远程端不显示入口，其余布局不变。

进入会话后显示并操作该会话的终端，沿用 Claude Code / Codex 原有的输入、菜单和交互确认。

MVP 不另做聊天式会话界面，不把 agent 的终端交互重新设计成消息卡片或业务按钮。

### iPhone / iPad 终端输入栏

终端下方常驻一行输入栏。键盘收起时它在屏幕底部，键盘弹出时跟着升到键盘上方。

**按键**：**Esc · Tab · Shift+Tab · Ctrl+C · ↓ · ↑**，点击即向当前会话发送对应按键。Shift+Tab 和 Ctrl+C 使用独立按钮，无需用户组合输入。不设 ← →：文字在输入框里编辑，光标用系统方式移动；会话里偶尔需要左右键时，用空格键滑动发送。后面是两个输入用的键：粘贴键，以及最右边的键盘键（见下文“弹出和收起键盘”）。这八个键等分一行，不横向滚动；屏幕宽时每个键宽度有上限，这组键居中，图标和文字大小不随宽度变化。

**输入框**：软键盘打的字先进一个系统原生输入框，复制粘贴、拖动光标、输入法都由系统处理。输入栏按输入框里有没有字切换：

- 没有字：显示八个按键。键盘的回车、退格直接发给会话（例如 ↓ ↓ 再回车选菜单）；按住空格键左右滑动，每滑过一个字符宽度向会话发送一次 ← 或 →。
- 有字（输入法还在组字也算）：显示输入框、发送按钮，最右边仍是键盘键。回车在输入框里换行，输入框随内容长高，最多约 5 行，再多在框内滚动；输入框长高时向上盖住终端，不改变会话的行列数。点发送，把整段内容作为一次粘贴发给会话，再发一次回车提交；发完输入框清空，变回八个按键。

发送的内容插在会话输入框的光标处。会话输入框里原有的文字读不到，会和发送的内容一起提交。

输入框关闭自动纠错、拼写检查、句首大写、智能引号和智能破折号，用户无需设置。收起键盘时输入框里的内容保留，下次弹出键盘时继续编辑。**粘贴键**用系统的粘贴按钮，不会每次弹出“允许粘贴”的确认。点它把文字粘进输入框，同时弹出键盘、切换成输入框，可编辑后再发送；剪贴板是图片或文件时交给终端，按原方式作为路径粘贴。有字时不显示粘贴键，长按输入框用系统菜单粘贴。输入框为空时用系统菜单粘贴图片或文件，同样交给终端。

**弹出和收起键盘**：输入栏最右边的键盘键一直在：键盘收起时点它弹出键盘，键盘弹出时（有没有字都一样）它变成收起图标，点它收起键盘。在输入栏上往下抹，或在终端上往下拖到输入栏，也会收起键盘；在终端区域内拖动只滚动历史。点终端只把点击交给会话（如点 Claude Code 的选项或“Jump to bottom”），不弹出也不收起键盘。

接了实体键盘时不用输入框，打字直接进终端，点终端即可在终端里打字；输入栏显示八个按键，点键盘键仍可改用输入框。

### 打开会话时是否弹出键盘

只有接下来要打字时才自动弹出键盘，其余情况先阅读，点输入栏的键盘键再弹出：

| 打开的会话 | 自动弹出键盘 |
| --- | --- |
| 刚在本客户端新建的会话 | 弹出 |
| 需要你输入（权限确认、菜单选择） | 弹出 |
| 从历史恢复的会话 | 不弹 |
| 已完成且未读 | 不弹 |
| 正在工作 | 不弹 |
| 已读、等待输入 | 不弹 |
| 已退出 | 不弹 |

回到前台时保持原样，不因此弹出或收起键盘。iPhone 与 iPad 规则相同；iPad 接了实体键盘时不会出现屏幕键盘，打开任何会话都直接可以打字。

## 功能范围

| 功能 | 远程端 MVP 行为 |
| --- | --- |
| Projects | 只读浏览被连接电脑已有的项目，不提供项目管理操作 |
| Session cards | 保留会话卡片，支持查看、新建、resume 和关闭 session |
| Live status | 保留，展示被连接电脑上的实际会话状态 |
| Notifications | 保留客户端连接期间的通知 |
| Session history | 保留，可浏览、搜索（按标题、提示词或会话 ID）并 resume 历史会话 |
| Bottom shell | 不提供 |
| Closed-lid sleep protection | 完全不参与，不读取或展示状态，不提供设置或初始化弹框 |
| Scheduled tasks | 完全不参与，不读取或展示状态，不提供管理页面或操作 |

除终端内的正常输入外，远程界面改变会话的操作只有三个：**新建 session、resume session、关闭 session**。不增加项目编辑、排序、会话重命名、定时任务管理等操作。

浏览、选择会话以及连接电脑属于使用客户端的必要操作，不增加被连接电脑的管理能力。

## 项目与会话

### 项目只读

远程端展示被连接电脑的项目。添加、移除、编辑项目及修改项目设置均在本地端完成；远程端不提供这些入口。

### 新建 session

用户在已有项目下新建 Claude Code 或 Codex 会话。默认 agent 沿用该项目在本地端的设置，远程端不修改默认设置。

创建成功后显示对应卡片并可进入终端。本地端同步看到该会话。

同一次新建操作不能因网络中断或重试产生多个会话；用户再次明确执行新建，则创建另一个会话。

### 打开运行中的 session

点击已经运行的卡片，进入同一个会话，不另外启动一个副本。手机与桌面操作的是被连接电脑上的同一个会话。

### Resume session

从 Session history 恢复原会话，保留原有上下文。若该会话已经打开，则进入已有卡片，不再重复启动。

恢复失败时显示失败，不擅自替换成新会话。

### 关闭 session

**点击卡片上的“关闭 session”，关闭被连接电脑上的对应 session，行为与本地端关闭一致。** 沿用本地关闭所需的确认规则，远程用户能够在当前客户端完成确认。本地端与远程端同步更新，历史仍按现有行为保留并可 resume。

关闭只作用于用户选中的 session，不影响其他会话。

### 本地与远程界面各自独立

远程端浏览、切换项目或会话，以及新建、resume session，都不改变本地界面当前选中的项目和会话。本地界面只同步卡片的增加、移除和状态变化，不跟随远程端切换画面；远程端同样不跟随本地端切换。

因此两端可以同时操作不同的 session。例如 iPhone 在 session A 中输入，本地同时在 session B 中输入，两者互不影响：A 按 iPhone 的行列数显示，B 保持本地行列数。两端同时操作同一个 session 时，按下文终端尺寸规则处理，由用户自行避免同时输入。

典型场景是同一用户离开电脑时用 iPhone，回到电脑前用本地端：回到电脑前看到的仍是离开时选中的 session，不会被 iPhone 上的浏览打乱；iPhone 未锁屏留在一旁时，两端也不会互相拉动画面。

## 连接中断与恢复

本节描述连接生命周期，与点击卡片上的“关闭 session”是独立行为。

- 远程客户端断网、退出 App 或主动断开连接，不等于关闭 session，不因客户端离开而结束电脑上的会话。
- iPhone 切到后台或锁屏时，用户无需手动断开，客户端也不因切后台主动断开。后台连接可能被系统挂起或中断，不保证持续在线。
- 返回前台时，普通网络中断可以自动重连；若连接已被其他客户端替换，则提示“已在其他设备连接”，保持断开，直到用户手动连接。
- 重新打开 App 时，若上次退出时仍处于连接状态，自动连接上次的电脑；若用户主动断开过，或连接已被其他客户端替换（包括退出期间被替换），则停在连接页，不抢回连接。
- 连接中断时明确显示不可用状态，不把旧的会话状态显示成仍在实时更新。
- 重新连接后恢复项目、卡片、历史和实际运行状态，并能够继续查看、操作原会话。
- 电脑上的任务是否能够继续，取决于电脑和本地端的实际运行情况；远程端不负责唤醒电脑或改变休眠设置。

## 单客户端连接与终端尺寸

- 每台服务端同时只允许一个远程客户端连接，iPhone 与桌面远程客户端共用这一名额。
- 新远程客户端连接成功后，自动替换旧连接，无需先在旧设备上手动断开。会话继续运行，本地输入不受影响。
- 被替换的客户端提示“已在其他设备连接”，不自动重连；用户可手动连接，避免客户端之间反复抢占。
- 终端尺寸以最近一次变化为准：远程端进入 session、调整窗口大小或 iPhone 回到前台时，按远程端尺寸显示；本地调整窗口大小时，按本地尺寸显示。
- 本地端与远程端每次发送输入时，都使用当前端的终端尺寸；若与会话当前尺寸不同，先调整尺寸再处理输入。因此 iPhone 即使始终停留在前台，也会在再次输入时恢复手机尺寸，无需重新进入会话或点击按钮。
- 各端（本地端、iPhone 与桌面远程客户端）触发输入尺寸对齐的操作仅限键盘输入（包括 iPhone 软键盘和输入栏的 8 个键）和粘贴。滚动查看历史、点击和选择文本均不触发尺寸对齐，即使这些操作会作为鼠标事件发送给会话。进入会话、回到前台及显示区域尺寸变化仍按上述尺寸规则处理。
- 尺寸对齐改变的是会话的行列数，不改变本地或远程窗口的大小。行列数取当前操作端显示区域实际能容纳的大小；本地输入时使用本地显示区域的当前行列数。
- 本地端与远程端均可输入，不锁定本地输入；由用户自行避免同时操作。
- 远程端离开该 session 或断开连接后，该 session 恢复本地终端尺寸。
- 不设置“查看／接管”模式或接管按钮，不进行多个远程客户端之间的尺寸协商。
- 会话使用远程端行列数时，本地窗口和显示区域保持原大小，不增加“正在按远程设备尺寸显示”等提示。

## Live status、历史与通知

Live status 和 Session history 以被连接电脑的实际信息为准。远程客户端保留查看运行状态、浏览历史和恢复会话的能力。

通知保留已有会话通知的含义，不增加定时任务通知中心或额外管理功能。MVP 只覆盖客户端连接期间的通知，**不实现 iPhone 退到后台或锁屏后的可靠推送**。

## 远程端完全不参与的功能

### Closed-lid sleep protection

远程端不读取状态、不展示状态、不提供设置、不触发或承接本地初始化弹框。相关行为完全依赖本地端已有的设置和运行情况。远程端对此功能无感。

### Scheduled tasks

远程端不读取任务状态、不展示任务列表、详情或运行记录，不提供创建、修改、启停、删除或立即运行入口，也不承接相关管理弹框。

即使用户在对话中让 agent 创建或操作了定时任务，远程端也不增加处理流程或管理能力。定时任务仍按本地端既有规则运行，远程端对此功能无感。本范围不改变 [定时任务产品设计](schedule-product.md) 中的本地行为。

### Bottom shell

远程端不显示底部 shell，不提供打开入口或对应快捷操作。

## MVP 验收重点

- 远程客户端验收仅覆盖同一台 Mac 上的 iOS 模拟器（iPhone 与 iPad）和桌面远程客户端，均通过 `127.0.0.1:端口` 连接本机隔离的测试服务端。iPhone 真机、另一台电脑和跨网络连接不在本次验收范围内。
- 两种客户端分别验收，并通过依次连接同一测试服务端验证新连接替换旧连接、旧客户端不自动抢回的行为。
- 终端下方常驻输入栏，提供 Esc、Tab、Shift+Tab、Ctrl+C、↓、↑ 和粘贴键，可操作当前会话的菜单和输入；组合键按钮一次点击即可发送。软键盘打的字进原生输入框，有字时输入栏换成输入框和发送按钮，发送时整段粘贴给会话再回车；输入框为空时回车和退格直接发给会话。点终端只是点击；键盘由输入栏最右边的键盘键弹出和收起，也可在输入栏上往下抹收起。
- 打开会话时按“打开会话时是否弹出键盘”的表格决定是否弹出键盘。
- iPhone / iPad 只提供远程使用；桌面能本地使用或连接另一台电脑。
- 远程端的项目列表、卡片、历史和搜索与本地端外观和交互一致；Mac 远程窗口和 iPad 为侧栏加终端，iPhone 侧栏为一整屏；触屏上长按打开本地的右键菜单。
- 本地远程服务默认关闭；Vertty 菜单的“远程连接”子菜单在“关闭”“通过 Tailscale”“自行组网”中三选一，记住选择，下次启动沿用。
- 选自行组网时子菜单显示端口与客户端连接状态，不列出地址。
- 默认使用端口 58563；设置 `VERTTY_REMOTE_PORT` 并重启后使用指定端口。启动失败时菜单显示失败及原因，不自动换端口、重试或弹窗。
- 自行组网输入 URL 即可发起连接，不要求账号、配对码或访问凭证；客户端与服务端之间的安全联通由用户自行保证。
- 远程端能浏览已有项目，但没有项目管理入口。
- 能新建、resume 和关闭 session；打开已运行会话不会新建副本。
- 新建操作重试不重复创建；重复 resume 已打开会话不重复启动。
- 关闭卡片与本地关闭行为一致，确认可在远程端完成，本地端与远程端同步更新。
- 远程端切换项目或会话、新建或 resume session，本地界面当前选中的项目和会话不变，反之亦然；两端可同时在不同 session 中输入，互不影响。
- 每台服务端同时只保留一个远程客户端连接；新连接成功后替换旧连接，会话继续运行。旧客户端显示“已在其他设备连接”，不自动重连。
- iPhone 切后台或锁屏无需手动断开，也不主动断开；返回前台可恢复普通断线，但不能自动抢回已被其他客户端替换的连接，包括后台期间未收到替换提示的情况。
- 终端尺寸以最近一次变化为准：远程端进入 session、调整窗口大小或 iPhone 回到前台时使用远程尺寸，本地调整窗口大小时使用本地尺寸；远程端离开后恢复本地尺寸。本地端与远程端均可输入，无需手动接管。
- iPhone 始终在前台时，本地手动放大终端后，手机再次输入会先恢复手机尺寸；随后本地输入也会先恢复本地尺寸，不需要额外按钮。
- 各端只有键盘输入（包括 iPhone 软键盘和输入栏 8 个键）和粘贴触发输入尺寸对齐；在任何一端滚动历史、点击和选择文本都不触发。对齐只调整会话行列数，不调整任何窗口大小。
- 断开连接与关闭 session 分开处理；重连后能继续进入原会话。
- Live status、Session history 和连接期间的 notifications 保留。
- 不实现 iPhone 后台或锁屏可靠推送。
- 远程端没有 Bottom shell、项目管理、休眠保护和定时任务管理入口。
- 休眠保护与定时任务的状态、设置、初始化或管理弹框不会进入远程端；agent 在对话中的操作也不改变这一范围。

### Tailscale 验收

- 用测试专用的 Tailscale auth key（临时设备，测试实例退出后由 Tailscale 自动删除）授权隔离测试实例和 iOS 模拟器，不登录用户自己的设备；auth key 只通过启动环境交给测试实例，不写进代码或仓库。
- 电脑端选“通过 Tailscale”后，子菜单显示账号、本机名称和客户端连接状态；切到“自行组网”或“关闭”后，Tailscale 上不再开放服务。
- Tailscale 方式下，电脑不在局域网等其他网络上监听端口。
- 客户端（Mac 远程窗口与 iOS 模拟器）登录后列出同一账号下的电脑，点选即连接；会话的查看、输入、新建、resume、关闭与自行组网一致。
- 不同账号的设备连不进来。
- 断线重连、被替换和重新打开 App 自动连接上次电脑的行为与自行组网一致。
- 退出登录后客户端回到未登录状态，电脑端显示“等待登录”。

## 技术限制

### 通信与协议定义

- `VERTTY_REMOTE_PORT` 沿用 README 中现有环境变量的登录 shell 读取方式。未设置时使用 58563；设置值须为 1–65535 的整数，配置无效或端口无法监听时显示启动失败及原因。实现时在中英文 README 的环境变量表中补充该变量、默认值与重启生效说明。
- 当前技术方案为一条 WebSocket 连接配合 Protobuf 消息定义。项目、会话、历史查询，会话操作，以及实时终端数据、状态和通知共用这一连接，不另拆 HTTP 业务接口。
- 使用独立的 `.proto` 文件定义消息和字段，并生成客户端与服务端使用的代码。iPhone 与桌面远程客户端共用同一份协议定义，通过 WebSocket 通信。
- 在 `.proto` 的消息定义和注释中写清楚版本兼容、请求与回复对应关系、错误返回、重复请求处理、重连恢复，以及单客户端连接限制、终端尺寸与输入行为。
- 自行组网时，客户端从用户填写的 URL 建立连接。两种方式都不依赖 Vertty 自建的云端转发服务（Tailscale 方式使用 Tailscale 自己的协调和中转服务）。

### Tailscale

- 用 Tailscale 官方的 `tsnet`（Go）把一台 Tailscale 设备嵌进 App：用户态网络，不需要系统 VPN、Network Extension 或 Tailscale App。Go 代码编成静态库，Mac 和 iOS 共用（`VerttyKit` 的 `VerttyTailnet`）。
- 远程协议不变。电脑端在 Tailscale 上监听 58563，校验对方设备属于同一用户后转给只监听 `127.0.0.1` 的远程服务；客户端每次连接先经 Tailscale 拨通电脑，再通过本机 `127.0.0.1` 上一次性的转发端口建立同样的 WebSocket。
- 设备的 Tailscale 主机名为 `<电脑或设备名>-vertty`，客户端据此和系统类型（macOS）从 Tailscale 设备列表里找出 Vertty 电脑。
- Tailscale 登录状态存在 App 的状态目录（Mac：`Application Support/Vertty/tailscale`）。

### 终端与执行环境

- Claude Code / Codex 继续运行在被连接的电脑上。手机内嵌终端显示和输入组件，不在手机上运行这些 agent 或本地项目。
- PTY 是电脑本地的终端接口，不是网络协议。远程连接传输终端输入输出字节和控制消息，客户端解析终端输出；用户输入写入对应会话的终端，不依赖模拟系统键盘或聚焦桌面窗口。
- iOS 优先评估原生 libghostty 集成。已有 [gterm](https://github.com/madeye/gterm) 和 [libghostty-spm](https://github.com/Lakr233/libghostty-spm) 等参考项目，但包含 iOS 适配和补丁，不能假定桌面端现有集成可以直接复用。具体依赖与适配方式需通过构建和运行验证后确定。结论：采用 libghostty-spm 预编译的 GhosttyKit 和它的 UIKit 终端视图（源码放在 `iOS/GhosttyTerminal`，改动见其中的 `VERTTY.md`），已在 iOS 模拟器里验证。
- 同一个 PTY 只有一套行列尺寸，采用最近一次由本地或远程端触发的尺寸变化。远程端进入 session 或 iPhone 回到前台时重新提交远程尺寸，离开后恢复本地尺寸；不实现本地与远程之间的输入锁定，也不因另一端的尺寸同步反复覆盖。
- 本地端与远程端每次发送输入时，一并携带当前端实际可用的终端行列数。服务端先比较会话尺寸，仅在不同时调整，再处理该次输入。当前端尺寸取自自身显示区域，不使用另一端同步过来的会话尺寸；该规则写入 `.proto` 定义和注释。
- 各端的输入尺寸对齐仅由键盘输入（包括 iPhone 软键盘和输入栏 8 个键）和粘贴触发；滚动历史、点击和文本选择即使作为鼠标事件写入会话，也不走输入尺寸对齐流程。调整 PTY 行列数不调整客户端窗口或显示区域大小。
- 重连不能只继续接收新输出，还需要恢复当前终端画面及必要的滚动历史；客户端断线不应销毁电脑上的会话。

### 会话操作与通知

- 现有本地 resume 会检查已打开的 session，已有终端不会因再次选择而重复启动；远程操作应复用这一行为。
- 现有新建操作每调用一次都会创建一个会话。远程请求需区分“同一次操作的重试”和“用户再次新建”，前者返回原结果，后者才创建新会话。
- 客户端不提取 Claude 的订阅凭证或自行代替 Claude Code 请求模型服务；agent 的登录和模型访问仍由电脑上的原版程序负责。
- WebSocket 连接不保证 iPhone 在后台或锁屏时持续运行。MVP 不引入后台可靠推送，仅保留客户端连接期间的通知。

### 代码共享

- Mac 本地窗口、Mac 远程窗口、iPhone 和 iPad 尽量共用一份代码，只有确实不同的地方才分别实现。
- 共用的部分只有一份实现，包括：项目列表与项目菜单，会话卡片（状态图标、Agent 图标、分支 / worktree / PR 行、卡片菜单），历史、显示更多与搜索，终端上方的标题条，远程连接状态与提示，以及远程会话的数据与操作（新建、resume、关闭及其确认、断线重试、通知、终端快照与尺寸处理）。
- 分别实现的只有：终端视图（两边是同一份 Ghostty，Mac 用 Vertty 自己的 AppKit 视图，iOS 用取自 libghostty-spm 的 UIKit 视图），键盘与输入栏，触屏适配（长按代替右键、长按菜单代替悬停按钮），布局（Mac 与 iPad 用侧栏，iPhone 侧栏为一整屏），以及连接入口等平台入口。
- 远程端不提供的本地功能（项目管理、排序、定时任务、默认会话设置、底部 shell 等），在共用代码里按端的能力隐藏入口，不为远程端另写一套界面。
- 新增或修改界面先改共用代码，不复制到某一端单独改。
- 共用代码放在 Swift 包 `VerttyKit`（协议、远程客户端和共用界面），Mac app 与 iOS app 都依赖它。

### 开发与验证环境

- iPhone 客户端的构建和模拟器验证需要完整 Xcode 及 iOS Simulator runtime，仅安装 Command Line Tools 不够。
- iOS 的界面、连接、终端交互、软键盘及中文输入均在本机 iOS 模拟器（iPhone 与 iPad）中验收，本次不要求真机验证。
- 本机桌面远程客户端与本机 iOS 模拟器均通过 `127.0.0.1:端口` 连接隔离的测试服务端。服务端本地界面用于核对会话同步、独立选择和尺寸规则，不要求另一台电脑或跨网络验收。
- 测试使用隔离项目与会话，不向用户真实会话发送测试输入。
