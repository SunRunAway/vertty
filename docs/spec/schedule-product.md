# Vhostty 定时任务产品设计

状态：已实现的产品规则。更新日期：2026 年 10 月 15 日。

用户为本地项目配置“每周六上午 9 点做什么”，Vhostty 到点在后台启动 Claude Code 或 Codex。一个任务固定使用一个会话：首次运行创建，后续触发均 resume 同一会话。用户通过运行记录进入会话查看结果、继续工作。

## 已确认的规则

- 同时支持 Claude Code 和 Codex，自动执行不抢当前焦点。
- 内置定时任务工具，支持在对话中查询、暂停、恢复和立即运行任务；创建、修改和删除直接生效，返回可打开任务侧栏的链接，不弹人工确认界面。
- 只有一种执行方式：首次新建会话，后续始终 resume 同一个会话，不提供执行方式或已有会话选择器。
- 提示词通过 agent 支持的 CLI 参数或标准输入提交；禁止模拟键盘、粘贴、回车或向交互终端注入提示词。
- 后续触发时，无论用户是否在 Vhostty 中打开该会话，都通过 resume 执行；已打开时先主动停止该会话的旧执行实例，允许打断用户，作为第一版已知缺陷。
- 错过时间后默认补跑最近一次，不提供策略选项。
- 同一任务不重叠；上次未结束时跳过本次并记录原因，不排队追补。
- 不做不同任务之间的工作目录串行调度。
- 列表合并展示运行状态，启动、执行、等待处理在详情中区分。

下文为第一版方案；列表文案和其余交互按此草案设计。

## 创建任务

| 配置 | 第一版行为 |
| --- | --- |
| 名称、项目、提示词 | 必填，项目从 Vhostty 已添加的项目中选择 |
| Agent | 默认选项目的 agent；首次创建会话后固定，不能切换到另一种 agent |
| 执行时间 | 单次、每天、工作日、每周；每周支持多选星期 |

示例：**每周依赖检查 · vhostty · Claude · 每周六 09:00 Asia/Singapore**。

第一版沿用 CLI 的模型、权限及项目配置，不增加每个任务的模型和权限设置面板。运行方式支持交互确认时，用户进入会话处理；如果执行接口只能返回权限错误，则显示异常，不能自动绕过权限或声称仍在等待确认。

名称和提示词不能为空，每周必须选择星期，单次时间必须在未来。时间按本机系统时区计算，系统时区变了就跟着变；夏令时不存在的时刻顺延到首个有效时刻，重复时刻只执行一次。

## 对话内管理任务

Vhostty 内置定时任务工具，随 App 发布和更新，并在启动 agent 时自动加载，不要求用户手动安装或写入全局配置。用户可以直接说“每周六检查依赖”“把依赖检查改到周日”或“暂停这个任务”，agent 根据请求自动使用这些工具；长对话被压缩后仍然可用。创建、修改和删除直接保存，成功后返回任务数据和 `vhostty://schedule/<UUID>` 链接。

- 所有工具直接执行；是否批准调用由 agent 自身的权限机制处理，Vhostty 不增加人工确认。
- 创建时优先使用当前项目和 agent，将对话中的必要背景整理成可独立执行的提示词；时间等必要信息不明确时询问，不擅自猜测。
- 创建任务的当前对话不直接绑定为执行会话；首次触发仍创建任务自己的会话，后续固定 resume。
- 修改前查询任务并按任务 ID 操作；多个任务匹配时询问，不误改或重复创建。
- 保存成功后回复操作结果，可以附任务链接；保存失败明确报错，不声称成功。
- Vhostty 定时任务请求使用这些工具，不改建为 Claude 云端任务、会话内定时任务或 loop。

### 任务链接

Agent 操作不打开侧栏、不抢焦点，也不受当前侧栏是否有未保存改动影响。创建、修改和删除的返回包含 `task` 和 `url`；查询返回的任务也带 `url`。用户点击链接时，Vhostty 打开对应任务侧栏。删除后链接仍可查看任务和运行历史。

人工新建和编辑继续使用侧栏，人工删除保留确认框。Agent 更新当前已显示的任务时刷新无未保存改动的侧栏，保留用户尚未保存的编辑。

## 界面与操作

侧栏项目列表上方提供带时钟图标的“定时任务”入口；点击后主内容区展示管理页面，原会话继续运行。项目的 `⋯` 菜单提供“新建定时任务”，预选该项目。不增加顶部标签栏。

### 人工新建

管理页标题栏右侧和每个项目分组的标题行提供“+”。点击后在窗口右侧打开任务侧栏，按“名称 → 提示词 → 详情（项目、agent、会话）→ 计划（频率、星期或日期、时间）”排列；提示词使用主要的多行输入区域，计划下方实时显示下次执行时间。

有改动时侧栏底部出现“取消”和“创建并启用”。人工创建点击一次即可完成，不叠加第二个确认弹窗；创建不会立即运行，用户可随后点击“立即运行”。

### 列表与任务侧栏

管理页按侧栏的项目顺序分组列出任务，不做状态筛选和搜索。每行是与会话卡片同风格的卡片：状态标记、agent 图标、名称，次行显示计划和下次执行（如“每周六 09:00 · 3天后”），上次运行异常时在后面标红。悬停时显示“立即运行”和 `⋯`（立即运行、暂停或恢复、打开会话、删除）。已删除的任务折叠在列表底部的“已删除”分组。空列表显示“还没有定时任务”。

点击一行在窗口右侧打开该任务的侧栏，与新建用同一个侧栏，可直接修改，有改动时底部出现“取消”和“保存”。侧栏顶部显示状态，提供立即运行、暂停或恢复、`⋯` 和关闭；下方是倒序运行记录，点击记录打开关联会话。已删除任务的侧栏只读。侧栏没有改动时切换会话会自动关闭；有未保存的改动时保持打开。

| 操作 | 行为 |
| --- | --- |
| 立即运行 | 使用当前配置执行一次，不改变原计划；运行中不可重复点击 |
| 编辑 | 只影响后续运行 |
| 暂停或恢复 | 暂停不终止当前运行；恢复从当前时刻安排，不补主动暂停期间及暂停前未处理的遗漏 |
| 删除 | 停止未来调度，移入列表的“已删除”，保留配置、记录和会话，不终止当前运行 |
| 打开会话 | 查看结果或继续对话；任务运行期间仅复用实际支持的查看或接入方式，不启动第二个同时写入该会话的实例 |

已删除任务在“定时任务”列表底部的“已删除”分组里，点开查看，包括没有会话的失败、跳过记录。配置只读，不能运行或恢复调度；尚未结束的运行继续更新。第一版不做恢复已删除任务和永久清除记录。

单次任务计划触发后不再安排下一次，时间栏显示“无后续计划”。执行结束后移入列表底部默认折叠的“已结束”分组，位于“已删除”之前，保留现有操作和运行记录；正在运行或重新安排了未来计划的任务仍在主列表。“已结束”仅表示调度结束，不表示执行成功。

首次创建的会话放在所属项目顶部，沿用四行卡片并加小钟标识，不切换当前选择、不抢焦点、不强制展开项目。后续 resume 复用该会话卡片，不重复创建；若用户正打开它，停止和重新执行会影响卡片内容，但不主动跳到其他卡片。任务名称不覆盖 agent 会话标题。

## 列表只展示四种运行状态

| 列表文案 | 表示什么 | 详情展示 |
| --- | --- | --- |
| 运行中 | 本次运行尚未结束 | 正在启动、正在执行或等待你确认，并提供“打开会话” |
| 已完成 | agent 跑完了这一轮，可以查看结果；不表示任务目标成功 | 开始和结束时间，以及“打开会话” |
| 异常 | 启动失败、执行报错、中断，或无法确认执行状态 | 具体原因及可用的处理操作 |
| 已跳过 | 本次没有提交提示词 | 跳过原因，例如同一任务上次仍在运行 |

使用“已完成”，跟侧栏卡片的说法一致；它只表示 agent 跑完了这一轮，不判断业务结果。查看会话后仍显示“已完成”，未读标记沿用现有逻辑。不使用绿色成功对勾。

等待用户确认仍归入“运行中”，列表可保留现有的注意提示，进入详情后说明需要处理什么。已知报错归为“异常”；agent 正常回复中说明“没有解决问题”仍可为“已完成”，第一版不自动理解回复内容来判定成败。

判断不了执行状态时直接记为“异常”并写明原因，不阻塞后续计划，也不需要用户手动解除。

## 会话执行

自动触发、补跑和立即运行均使用以下同一流程：

1. 先检查同一任务上次运行是否结束。未结束则跳过，不为新一轮强行停止上一轮。
2. 首次在项目目录创建会话，保存 agent 类型、完整会话 ID 和执行目录，再关联当次运行。会话一旦创建成功，后续即使运行失败也继续使用它。
3. 后续始终按固定 ID resume。若 Vhostty 正打开这个会话，先停止对应的旧执行实例，确认停止后再 resume 并提交本次提示词；用户是否正在查看、输入或手动让 agent 工作，不改变此流程。
4. 通过 CLI 参数或受支持的非交互标准输入传递提示词，不向已有交互终端写入文本。必须避免出现两个实例同时执行同一会话。

停止必须只针对该任务绑定的会话，不关闭其他会话、共享 daemon 或无关 shell。关闭终端或断开 attach 不等于后台 agent 已停止；不能确认停止时显示异常，不冒险启动第二个实例。Vhostty 外部的占用不自动强停，无法确认时也显示异常。

绑定不跟随卡片后来的 `/clear`、`/new` 或会话切换；卡片已经换到其他会话时不能因卡片相同就停止它。会话或目录不存在、恢复失败时显示异常，不自动换目录、重建会话或 fork。首次创建结果不明时先核对，不因缺少会话 ID 就反复新建。

### 第一版已知缺陷

定时触发会主动停止用户在 Vhostty 中打开的任务会话，可能打断手动工作、权限确认，或丢失未发送输入。第一版接受这一行为，不做忙闲等待、输入保留或逐次确认；这一点只记在文档里，界面不另加提示。用户可提前暂停任务避免打断。

这里被打断的是用户手动接手后的会话操作；同一任务上一轮仍在运行或等待处理时，仍按防重叠规则跳过新一轮。

## 调度与补跑

Vhostty 运行且电脑醒着时执行。关闭窗口但 App 仍运行可以调度；退出 App 后不再发起新运行。第一版不增加后台常驻服务、自动唤醒或退出时杀进程的行为。

App 启动、电脑唤醒后，只补跑启用任务最近一次尚未处理的过期计划，不设补跑开关和天数窗口。更早的遗漏不补跑，也不记录；后续仍按原计划触发。

补跑同样先检查同任务防重叠，再按停止旧实例和 resume 的流程执行。失败和已跳过的运行不自动重试。新建任务从保存时开始；修改时间规则从修改时重新安排，不追补旧规则的遗漏。

同一计划时间不能因多次检查、唤醒或重启而重复提交。重启时上次未结束的运行记为“异常”。

## 运行记录

每次计划触发、补跑和手动执行均独立记录，即使使用同一个会话。详情保留计划时间、实际起止时间、触发来源、四种状态之一、原因和关联会话，支持加载更早记录。当次提示词在会话里查看，不另存快照。

点击记录进入关联会话；没有会话时查看原因。第一版不做消息级跳转、对话副本或 AI 摘要。记录独立于会话保留，外部删除会话不删除运行记录。

权限确认、未读标记及系统通知沿用现有会话行为，系统通知继续来自 agent 的 OSC 9/777。启动失败等无 agent 通知的情况在任务列表中显示异常。

项目被移除或目录被修改时不自动暂停任务；到点时项目或目录不在，就记一次“异常”并写明原因。

## 第一版暂不做

- 云端执行、App 退出后执行、自动创建和清理 worktree。
- 不同任务的目录锁、排队、全局并发管理。
- App 内独立的自然语言解析器、自定义 cron、事件触发、任务依赖；对话中的自然语言由 agent 配合内置工具处理。
- 每次新建或选择已有会话的模式、每任务的模型和权限面板、自动重试、业务成功判断。
- 全局历史页面、结果摘要生成、永久删除与回收站恢复。

## 验收重点

- 可创建“每周六 09:00”任务，显示正确的下次时间。
- Vhostty 启动的 Claude Code 和 Codex 均能发现内置工具，无需写入全局配置；支持自然语言请求，长对话压缩后仍能发现。
- 人工新建有明确入口，同一个侧栏一次确认即可创建；列表能查看计划、下次时间和状态，任务侧栏可管理任务及打开运行记录。
- Agent 打开预填好的同一个任务侧栏或确认框；人类可修改后确认，取消则什么都不留。
- Skill 的创建、修改和删除都不能直接生效；接口拒绝绕过确认。
- 对话内必要信息缺失或目标不明确时询问，打开侧栏后不宣称任务已创建，创建对话不被绑定为执行会话。
- 首次创建会话，后续自动、补跑和手动触发始终 resume 原 ID，每轮都有记录；无执行方式和会话选择器。
- 提示词通过正式 CLI 输入接口提交，不模拟键盘、粘贴或向交互终端注入文本。
- 会话在 Vhostty 中打开时，先停止旧实例再 resume；允许打断用户，作为已知缺陷记在文档里，界面不另加提示。未打开时直接 resume。
- 停止范围只包含绑定会话；无法确认旧实例停止时不重复启动，不影响其他会话或共享 daemon。
- 不主动切换当前卡片或抢焦点；同一任务上一轮仍在运行时跳过，不强停它。
- 错过多次只补最近一次；同任务未结束则跳过；不同任务不按目录排队。
- 列表只有四种运行状态；详情区分启动、执行、等待确认；已完成不暗示成功，也不随已读改变。
- 当前运行不会被下一次跳过记录遮盖；异常明确显示原因。
- 暂停不补积压，删除后仍可从“已删除”查看全部历史。
- 重启和重复唤醒不重复提交，运行记录不随任务编辑或会话丢失而消失。

实现前需验证两种 agent 的固定 ID resume、非键盘提示词提交、会话级停止、轮次结束识别和重启恢复，以及执行期间是否支持查看或交互确认。CLI 参数存在不等于停止和恢复流程已经验证通过；关闭终端或标题停止转圈也不能单独证明 agent 已停止或任务成功。测试使用隔离状态目录和 debug driver，不向用户真实项目会话发送测试输入。
