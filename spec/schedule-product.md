# Vhostty 定时任务产品设计

状态：产品草案，尚未实现。更新日期：2026 年 10 月 13 日。

Vhostty 支持用户为本地项目安排 Claude Code 或 Codex 定时任务，例如“每周六上午 9 点检查依赖”。任务到点后在后台执行，用户可以查看每次运行的记录，并进入对应会话继续工作。

本文用于确定第一版的产品范围、交互和验收标准，不规定调度器、存储格式或 CLI 调用方式。

## 已确认的产品要求

- 同时支持 Claude Code 和 Codex。
- 每个任务可选择“每次新建会话”或“继续指定会话”。
- 自动执行不抢当前会话焦点。
- 因 App 未运行或电脑休眠错过执行时间时，恢复后默认补跑最近一次，不提供策略选项。
- 同一个任务不重叠执行。下一次到点时，上一次仍未结束，则跳过本次并记录原因。
- 不做不同任务之间的工作目录串行调度；多个任务可以在同一工作目录执行。

以下内容是基于这些要求制定的第一版产品方案。运行历史、界面入口和其他边界行为按本草案设计，可在产品评审时调整。

## 用户场景

| 场景 | 配置 | 预期结果 |
| --- | --- | --- |
| 每周独立检查 | 每周六 09:00，在 vhostty 项目新建 Claude 会话检查依赖 | 每周结果独立，查看记录可进入当次会话 |
| 持续跟进事项 | 每个工作日 10:00，继续指定 Codex 会话检查 PR 进展 | 沿用同一会话上下文，每次触发仍有独立运行记录 |
| 临时安排工作 | 明天 15:00 执行一次检查 | 执行一次后计划结束，保留任务和运行记录 |
| 错过执行时间 | 周六电脑休眠，周日打开 Vhostty | 自动补跑最近一次，记录原计划时间和实际开始时间 |
| 手动验证任务 | 创建后点击“立即运行” | 立即执行并查看权限和结果，不改变周期任务的下次计划时间 |

## 第一版范围

第一版包含任务创建与管理、时间配置、两种会话执行方式、自动补跑、同任务防重叠、运行记录和会话接手。

任务在本机运行，使用已安装并登录的 Claude Code 或 Codex。Vhostty 必须处于运行状态，电脑必须处于唤醒状态。关闭窗口但 App 仍运行时继续调度；退出 App 后不再发起新运行，重新启动后按补跑规则处理。退出 App 不增加杀掉 agent 或其子进程的行为。

第一版不包含：

- App 退出后的常驻调度服务、自动唤醒电脑或云端执行。
- 自动创建或清理独立 worktree；新建会话使用任务所属项目目录。
- 跨任务的目录锁、执行队列或全局并发控制。
- 自然语言配置时间、自定义 cron、任务依赖、事件触发。
- 自动重试失败任务、自动判断业务目标是否达成。
- 单独的全局运行历史页面、额外调用模型生成运行摘要。

## 任务配置

| 字段 | 行为 |
| --- | --- |
| 名称 | 必填，供任务列表和详情展示；与 agent 会话标题独立 |
| 项目 | 必填，从 Vhostty 已添加的项目中选择 |
| 执行方式 | “每次新建会话”或“继续指定会话”；默认新建 |
| Agent | 新建模式默认使用该项目当前默认 agent，保存后固定；继续模式由目标会话决定 |
| 目标会话 | 仅继续模式显示，选择该项目中的已有会话，必须能确定完整会话 ID |
| 提示词 | 必填，每次触发提交的工作指令；编辑后仅影响后续运行 |
| 时间规则 | 单次、每天、工作日、每周；每周支持选择多个星期 |
| 时间与时区 | 明确显示执行时间和时区；默认使用创建时的系统时区，保存后不随旅行自动改变 |
| 权限模式 | 默认沿用 agent 配置；可选择该 agent 实际支持的权限模式，不自动扩大权限 |

模型及其他 agent 配置第一版沿用 CLI 设置，不增加完整的模型配置面板。

时间表单显示可读摘要及下次执行时间，例如“每周六 09:00，Asia/Singapore”。单次任务只能选择未来时间。每周至少选择一个星期。名称、提示词和必要字段缺失时不能保存。

按所选时区的日历时间执行，不把“每天”简单解释成每隔 24 小时。夏令时导致某次时间不存在时，在该日时间跳变后的第一个有效时刻执行；同一日时间重复出现时只执行一次。

### 会话选择

会话选择器包含该项目已打开和历史中的 Claude / Codex 会话，支持按标题搜索，显示 agent、标题、分支或工作目录，以及可辨认的会话 ID。

任务绑定 agent 类型和完整会话 ID，不绑定标题或卡片位置。卡片后来执行 `/clear`、`/new`、`/resume` 或切换到其他会话，不改变任务原来的绑定。目标会话丢失时显示错误，不自动改成新建模式。

继续模式沿用目标会话的工作目录；该目录不存在时本次失败，不悄悄改用项目主目录。第一版不负责重建已删除的 worktree。

## 界面与主要操作

侧栏增加“定时任务”入口，进入全部任务列表；项目的 `⋯` 菜单增加“新建定时任务”，打开时预选该项目。不增加顶部标签栏。

任务列表展示名称、项目、agent、执行方式、计划摘要、启用状态、下次执行时间和最近一次运行状态。点击任务打开详情。

任务详情展示配置和运行记录，提供以下操作：

| 操作 | 行为 |
| --- | --- |
| 立即运行 | 使用当前已保存配置执行一次；受同任务防重叠规则约束；周期计划保持不变 |
| 编辑 | 修改后续运行配置，不改变正在执行的运行和过去记录 |
| 暂停 | 停止未来自动触发，不终止正在执行的运行 |
| 恢复 | 从恢复时刻计算下次计划；主动暂停期间不产生补跑 |
| 删除 | 停止未来调度并移除任务定义，保留已有会话及运行记录；不终止当前运行 |
| 打开会话 | 查看执行过程、处理审批，或继续对话 |

暂停中的任务可以“立即运行”，运行后仍保持暂停。单次任务提前手动运行属于试运行，不消耗未来那次计划；计划触发后标记为“已结束”，失败也不自动再次触发。

自动新建的会话卡片放在所属项目顶部，沿用现有四行布局，以小钟图标标识定时任务来源。后台启动不切换当前卡片、不抢键盘焦点、不强制展开项目。继续已有会话时复用其卡片，不创建重复卡片。

任务名称可编辑，但不通过任务页面重命名 agent 会话。卡片标题继续使用现有 agent 标题来源。

## 执行规则

### 新建会话

每次运行创建新的独立会话，并提交任务提示词。新会话沿用项目指令和 agent 配置，不继承其他会话的对话上下文。

会话创建成功不等于提示词已提交。运行记录必须能区分正在启动、实际执行和启动失败，避免出现“开了终端但没有干活”却显示完成的情况。

### 继续指定会话

| 目标状态 | 执行动作 |
| --- | --- |
| 已在 Vhostty 打开且可接受新消息 | 在原会话提交提示词，不再次 resume 同一会话 |
| 尚未打开且可以恢复 | 后台 resume 指定会话，恢复完成后提交提示词 |
| 正在工作、等待审批或等待回答问题 | 跳过本次，记录“目标会话正忙或等待处理”，不排队插入消息 |
| 无法恢复、目录不存在或会话不存在 | 本次失败并显示原因，不改换目标 |
| 无法确认是否可安全提交 | 不盲目输入，记录无法确认的原因，允许用户检查后手动再运行 |

两个不同任务绑定同一会话时，也遵循目标会话忙闲规则，不能同时向它提交提示词。这是会话可用性检查，不扩展为工作目录级串行调度。

### 防止重叠和重复触发

同一任务在启动、执行或等待用户处理期间视为尚未结束。下一次计划到点时记录一次跳过，且不在上次结束后补执行这次已跳过的运行。运行中的任务禁用“立即运行”。

同一计划时间只能被领取执行一次，周期检查、App 激活、系统唤醒和重启不能重复提交提示词。崩溃后如果无法确认提示词是否已提交，记录“待核对”，禁止自动重发；用户可查看会话后结束该条记录，再决定是否立即运行。

### 默认补跑

App 启动或电脑唤醒时，检查启用中的任务。存在尚未处理的过期计划时，自动补跑最近的一次，其余更早的计划记为跳过，可合并显示时间范围和次数。补跑不设置额外的天数窗口，也不提供开关。

例如连续错过三个周六，恢复后只执行最近那个周六的任务。补跑记录同时保存原计划时间和实际开始时间，后续仍按原来的星期与时间触发。

补跑也受同任务防重叠和目标会话忙闲规则约束；因此跳过的运行不再次补跑。已经失败、已跳过或人工结束的运行不会被当作“错过时间”。

新建任务从保存时开始安排，不能补跑创建之前的时间。修改时间规则从保存时刻重新计算未来计划，不补跑旧规则下的遗漏。暂停期间不积累遗漏；恢复时也不补跑暂停之前尚未处理的过期计划。

## 运行记录与会话接手

每次自动触发、补跑和手动执行各有一条运行记录。多次 resume 同一会话仍分别记录，不能用一条会话记录代替所有运行。记录显示在所属任务详情下，默认按时间倒序，支持加载更早记录。

记录包含任务名称、触发来源、原计划时间、实际开始和结束时间、状态、原因、agent、会话 ID 和执行目录。保留当次提示词及关键配置快照，后续修改任务不能改变过去记录的含义。已删除任务的记录随关联会话保留，不再产生任务列表入口。

| 状态 | 含义 |
| --- | --- |
| 启动中 | 正在创建或恢复会话，尚未确认开始执行提示词 |
| 执行中 | 已提交提示词，agent 正在处理 |
| 等待处理 | agent 需要审批或问题回答；仍占用该任务本次运行 |
| 已结束 | 已确认本次提示词对应的工作轮次结束；不代表业务目标成功 |
| 失败 | 已知的启动、恢复或执行错误，显示具体原因 |
| 已中断 | 已确认本次执行被取消或进程提前结束 |
| 已跳过 | 未提交提示词，显示原因 |
| 待核对 | 无法确认是否提交、是否结束或是否仍在运行，不能宣称成功 |

“待核对”记录提供“打开会话”和“结束本次记录”。后者仅解除任务占用并保留人工处理标记，不发送提示词、不停止进程。下一次触发仍需检查目标会话是否可用。

点击有会话的记录，打开或恢复关联会话；没有会话的失败、跳过记录只展示原因。第一版不要求定位到某条具体消息，也不复制整份对话日志。

接手后用户直接在现有终端中操作。未读标记和系统通知沿用 Vhostty 现有行为；系统通知继续来自 agent 的 OSC 9/777，不新增基于 hooks 的任务完成通知。启动失败等没有 agent 通知的情况在任务列表和记录内呈现。

## 异常与数据保留

- CLI 不可用、登录失效、权限不足或执行目录不可用时，展示可理解的原因；周期任务保留后续计划，不自动重试当前运行。
- 删除项目时一并停用关联任务，避免后台继续向已移除项目发起工作；保留任务配置和历史，重新指定项目后才能恢复。
- 修改项目路径时，关联任务暂停并提示重新核对目录和目标会话，不能静默切换执行位置。
- App 重启后保留任务、运行记录和会话绑定。先核对未结束运行，再处理补跑，不能直接假定之前的进程已经停止。
- 会话记录被外部删除时，运行记录仍保留，但“打开会话”显示目标不可用。
- 权限审批不由 Vhostty 模拟批准；不能通过改权限配置把“等待处理”伪装成无人值守成功。

## 验收标准

| 场景 | 必须满足 |
| --- | --- |
| 周任务配置 | 可设置“每周六 09:00”，明确显示时区和正确的下次执行时间 |
| 新建模式 | 连续两次运行产生不同会话 ID，各自记录对应关系 |
| 继续模式 | 连续两次运行使用指定会话 ID，有两条独立运行记录 |
| 已打开的空闲会话 | 复用原会话，不启动重复的 resume 客户端 |
| 目标会话忙碌 | 不插入提示词、不抢占，记录跳过原因 |
| 会话身份变化 | 原卡片切换会话后，任务仍绑定原 ID；不存在则失败 |
| 后台执行 | 当前选中卡片、输入焦点不变，用户输入不被定时任务覆盖 |
| 多次遗漏 | 恢复后只补跑最近一次，不补全部，不出现策略选择器 |
| 同任务重叠 | 上次未结束时下一次跳过；上次结束后不追补这次跳过 |
| 同目录不同任务 | 不因为工作目录相同而排队或拦截 |
| 手动运行 | 不改变周期计划，运行中不能再手动启动同一任务 |
| 暂停与删除 | 暂停期间不补跑；删除停止未来计划且不删除会话、不终止当前工作 |
| 重启与重复事件 | 同一计划时间不重复提交；状态不明时显示待核对 |
| 权限交互 | 遇到审批或问题可以进入会话处理，不显示为任务成功 |
| 失败可查 | CLI、目录、会话恢复失败都能从任务详情看到原因 |
| 配置编辑 | 过去记录保留当次配置，正在执行的运行不被修改 |
| 时间边界 | 时区固定、系统时钟回拨和夏令时重复时段不会重复触发同一轮 |

实现验证使用隔离状态目录、测试创建的会话和 debug driver，遵循仓库的 AGENTS.md 与 DEVELOPER.md；不向用户真实项目的会话发送测试提示词。

## 实现前需要验证的能力

以下是影响产品行为的技术验证项，不代表能力已经具备：

- Claude 与 Codex 是否能可靠地向新会话、恢复会话、已打开的空闲会话提交提示词，同时不覆盖未发送的用户输入。
- 如何识别本次运行的开始、结束和等待处理状态。终端标题变为空闲不能单独证明任务成功，CLI 启动时的转圈也不能计为任务开始。
- 指定会话在 Vhostty 之外运行时，如何识别占用；无法确认时按“待核对”处理，不重复接入并提交。
- 崩溃或重启后如何核对会话与运行记录，避免提示词重复提交。
